# Pi EasyMeet Bridge

A lightweight pi extension that connects an EasyMeet room to your current pi session. Messages posted in the room's chat are forwarded to pi as user prompts, and pi's assistant responses are sent back to the room using your configured display name.

## Features

- Configurable EasyMeet server, room code, display name, and password via `easymeet.json` or the `/easymeet-setup` command.
- Automatic handshake with the EasyMeet REST API (`POST /api/join`) followed by a persistent Protoo WebSocket connection.
- Bi-directional chat bridge:
  - Incoming EasyMeet chat messages become `[easymeet]`-prefixed user prompts in pi.
  - Assistant responses generated by pi are relayed back to the EasyMeet chat.
- Automatic reconnection with exponential back-off when the WebSocket drops.
- Status and lifecycle commands to connect or disconnect the bridge on demand.

> **Note:** This bridge focuses on EasyMeet chat. Audio/video transport, file transfers, polls, and reactions are ignored.

## Installation

1. Install dependencies:

   ```bash
   cd pi-easymeet-bridge
   npm install
   ```

2. Copy the sample configuration to your pi agent directory (if it does not exist yet) and adjust the values:

   ```bash
   mkdir -p ~/.pi/agent
   cp easymeet.json ~/.pi/agent/easymeet.json
   ```

   | Field                | Description                                                                            |
   |----------------------|----------------------------------------------------------------------------------------|
   | `serverUrl`          | Base URL of your EasyMeet deployment (e.g. `https://easymeet.easyroomtools.tech/`)     |
   | `roomCode`           | Room identifier / join code                                                             |
   | `displayName`        | Name shown for the bridge inside EasyMeet                                              |
   | `password`           | Room password (optional)                                                               |
   | `clientId`           | Unique client identifier (autogenerated if left empty)                                 |
   | `requireMention`     | `true` (default) → only forward messages that mention a wake word. Set `false` to respond to every message (sample above). |
   | `respondToQuestions` | `true` (default) → allow question-mark messages through even without a mention         |
   | `wakeWords`          | Additional aliases that count as mentions (case-insensitive). Default includes `"pi"`. Leave empty when `requireMention` is `false`. |
   | `respondOnlyTo`      | Optional allowlist of participant nicknames. When set, only messages from these names are forwarded. |
   | `ignoreParticipants` | Optional blocklist of participant nicknames. Messages from these names are never forwarded. |

   Example configuration:
   ```json
   {
     "serverUrl": "https://easymeet.easyroomtools.tech/",
     "roomCode": "ZOCKERTAG",
     "displayName": "Pi Assistant",
     "password": "",
     "clientId": "",
     "requireMention": false,
     "respondToQuestions": true,
     "wakeWords": [],
     "respondOnlyTo": [],
     "ignoreParticipants": []
   }
   ```

3. Register the extension with pi. From your project, run pi with the extension, for example:

   ```bash
   pi -e ./pi-easymeet-bridge/src/index.ts
   ```

   > If you want the bridge available automatically, place the directory under `~/.pi/agent/extensions/` or add it via `settings.json`.

## Usage

Inside pi, the extension provides the following commands:

| Command               | Description                                |
|-----------------------|--------------------------------------------|
| `/easymeet-setup`     | Prompt for server URL, room code, etc.      |
| `/easymeet-connect`   | Join the configured EasyMeet room           |
| `/easymeet-disconnect`| Leave the room and stop the bridge          |
| `/easymeet-status`    | Show current connection status              |

When the bridge is connected:

- Every chat line is stored in the session as a hidden observation so the agent can review the transcript.
- You can allowlist or ignore specific EasyMeet nicknames via `respondOnlyTo` and `ignoreParticipants`.
- The default wake word list already contains `pi`, so messages addressing “pi” will be forwarded when mentions are required.
- A message is only forwarded as a prompt when it contains one of the configured wake words (case-insensitive) or – if `respondToQuestions` is enabled – looks like a question. That way the agent stays silent unless addressed or it truly needs to respond.
- Forwarded messages appear in pi prefixed with `[easymeet] <nick>:` and can trigger a reply.
- Pi's assistant replies are sent back to the EasyMeet chat under the configured `displayName`.
- System tools such as `bash`, `write`, `edit`, `apply_patch`, `delete`, `copy`, `python`, and `node` are blocked automatically for EasyMeet-driven turns to protect the host environment.
- If pi is already busy when a chat message arrives, the bridge queues it and delivers it as a follow-up once the current turn finishes.

## Limitations & Notes

- The bridge only relays plain chat messages. EasyMeet file transfers, polls, emoji reactions, and video events are ignored.
- Ensure the EasyMeet room exists and allows new participants (the bridge connects as a regular client).
- The REST call to `/api/join` uses the `X-Easymeet-Client-Id` header. The `clientId` value is persisted in `~/.pi/agent/easymeet.json` after the first run to reuse the same identity.
- The WebSocket reconnect timer is a simple fixed delay (3 seconds). If credentials are wrong, the bridge keeps retrying until disconnected.
- This project depends on Node.js 18+ (pi currently ships with Node 22). No bundling step is required; pi executes the TypeScript entry point via jiti.

## Development

- `npm run lint` / `npm run build` scripts are not defined; run `npx tsc --noEmit` to type-check.
- The code uses the `protoo-client` package (same library as the official EasyMeet front-end) for signaling.

Feel free to extend the bridge with richer EasyMeet features (file transfers, reactions, UI status updates) as needed for your workflow.
